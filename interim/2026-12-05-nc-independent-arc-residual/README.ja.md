## 原因調査

対象の55×55系は `A=[[K,-dF/dλ],[t_u,t_λ]]`、`b=[0,…,0,1]`。54変位自由度とλを含み、元の弧長の単位換算は1 m。従来は NumPy `linalg.solve`（倍精度LAPACK gesv、部分ピボットLU）の1回求解だった。

元の残差は **`||A x-b||₂ / max(||b||₂,1e-30)`**。各成分を別の許容差で判定せず、無限大ノルムでも後退誤差でもない。ここでは `||b||₂=1` なので元の絶対L2残差と同じになる。剛性×変位速度とλ荷重項の大きな積が平衡行で相殺する一方、拘束行と右辺は約1であり、行・列の尺度が揃っていない。

新規Linuxの前史400・修正前8点から、最大残差だった**実際の正規化前の解と行列**を保存した。PCの行列を再現したものではない。

## 対策と失敗時の扱い

`independent_arc.py` の独立拡張系だけに、行の最大絶対値と、その後の列の最大絶対値による正の対角平衡化を加えた。`R A C y=R b, x=C y` を部分ピボットLUで解き、同じ分解を使って最大4回反復改良する。補正右辺はLinuxで追加精度のあるlongdouble、Windows型のlongdoubleではPython 3.12以降の拡張精度 `math.sumprod`、未対応Pythonでは50桁Decimalで計算する。`b` も内積に含め、拘束行の相殺を保つ。

元の直接解・平衡化直後・4補正の残差は全て記録し、**元のA,bに対する従来のfloat64 L2残差が最小の実解**を使う。良くならない補正で解を置き換えない。基準1e-10は変更せず、最終解が超過・非有限なら失敗のまま止める。高精度残差や後退誤差を受入の代用にしない。剛性の変更・対称化・固有値切捨て・追加拘束はない。弧長の1 m換算・RK4・材料写像・本体ソルバー・物理・既定・許容値は変更していない。

Windows型精度をLinux上で強制した保存系の補正分岐試験では、sumprod/Decimalとも元の残差 **4.03798e-11**。単一求解の参考時間は約0.00124秒／0.0106秒で、sumprod経路は既存180秒上限内の実行に有利。これは**Windows実機の時間や結果ではない**。詳細は [`portability-measurements.json`](portability-measurements.json)。

旧版は正規化した接線から解を代数的に戻して保存しており、再測定値が実際の検査値とずれる余地があった。今回は**正規化前の実解をそのまま、残差検査の前に保存**する。元の封印アーカイブ内の旧観測・失敗は変更しない。
