# NC-01・96 Tet10 の真の線形残差

作業起点は PR #13 の `e4e2dfd5c7bc189ccb471ab9cfe8621792e7b22f`。元の負荷・撤去履歴、工程試行数、カットバック条件を使い、線形求解だけを比較した。全経路で、有限な解と元の未スケール系の **‖Ax−b‖₂/max(‖b‖₂, 1e−30) ≤ 1e−10** を、既存と同じ nalgebra の行列積で検査する。

## 設定・アルゴリズムと停止則

4案は `settings.dense_residual_method` に下表の値を一つ指定する。いずれも通常の部分ピボット LU を先に解き、元残差が有限で許容値を超えた場合だけ追加計算する。設定を省略した場合は従来の dense LU。従来の `dense_lu_refinement=true` は従来のまま1回補正する。新設定と既存の1回補正の同時指定、疎 GMRES との併用、未知の手法名は入力エラーになる。

|案・設定値|計算と停止|
|---|---|
|1 `repeated_refinement`|現行の FMA と Neumaier 型の補償和で r=b−Ax を作り、同じ LU で Aδ=r を解いて x←x+δ。各更新で元ゲートを評価する。最大5回、過去最小の元残差を2回続けて更新できなければ停滞で停止する。|
|2 `extended_residual`|積の高位と FMA で回収した積誤差を、それぞれ2段の TwoSum に通して第3成分に残りを加える。b から各積を引いた後に3成分をまとめ、binary64 の補正右辺に丸める。既存 LU の補正・解更新は各1回。高精度化の対象は補正用残差だけ。|
|3 `ruiz`|通常 LU の棄却時に元行列から開始。各行・列の∞ノルムを同時に求め、それぞれの平方根の逆数を左右から掛ける。右辺に行尺度、解に累積列尺度を適用する。最大8掃引、全ノルムの1からの偏差が0.05以内、または最大偏差が改善しなければ平衡化を終了。零行・零列は棄却する。一度だけスケール後の系を LU で解き、元座標で判定する。|
|4 `gmres_polish`|固定した LU を右前処理 M とする GMRES(1)。通常精度の r=b−Ax から z=M⁻¹r、w=Az を作り、‖r−αw‖₂ を最小とする α=((w/‖w‖₂)ᵀr)/‖w‖₂ で x←x+αz。毎回元座標の残差を再計算して再始動する。最大5回、2回続けて最良値を更新できなければ停止。零または非有限の像は棄却する。|

**文献と実装上の選択。** Higham（2002）の *Accuracy and Stability of Numerical Algorithms* 第12章と Higham（2023）の残差・補正方程式、Carson & Higham（2018）の Algorithm 1.1 と Table 1.3 に従い、分解、補正右辺、解更新の精度を区別した。Anderson ら（1999）『LAPACK Users’ Guide』の “Driver Routines / Linear Equations” と実装を参照した。DGERFS の refinement loop は同じ因子の三角求解を繰り返し、ITMAX=5 と後退誤差の改善を打切りに使う。ここでは回数上限を参照し、実際の NC 判定残差の2回連続の非改善を停滞条件に選んだ。[Higham, 第12章](https://doi.org/10.1137/1.9780898718027)・[Higham, What Is Iterative Refinement?](https://nhigham.com/2023/03/13/what-is-iterative-refinement/)・[Carson & Higham](https://eprints.maths.manchester.ac.uk/2629/1/cahi18.pdf)・[LAPACK Users’ Guide](https://www.netlib.org/lapack/lug/node26.html)・[LAPACK, DGERFS](https://github.com/Reference-LAPACK/lapack/blob/6ec7f2bc4ecf4c4a93496aa2fa519575bc0e39ca/SRC/dgerfs.f)

Ogita・Rump・Oishi（2005）§§3–5 の誤差なし変換と補償内積が案1・2の根拠。既存1回補正では積の丸めを FMA で回収し、加算誤差とまとめて1本の補償和に集める。案2では低位成分にもう一段の誤差なし加算を施す。三角求解と解ベクトルは binary64 のまま。三成分の和は有限長であり、任意の入力に対する厳密算術の保証は置かない。[Ogita・Rump・Oishi, Accurate Sum and Dot Product](https://doi.org/10.1137/030601818)

Ruiz（2001）Algorithm 2.1 の同時平衡化を案3に選び、元座標への写像は LAPACK DGESVX の手順1・6を参照した。0.05 は掃引を止めるための行列ノルム偏差であり、線形ゲートには使わない。Saad & Schultz（1986）§3 の最小残差・再始動 GMRES と Carson & Higham（2018）§8 の LU 因子による前処理を案4の根拠とした。今回は元残差を再計算するたびに基底を破棄する1次元の右前処理版を選択した。前処理は固定で、基底1本の最小二乗問題には上の閉形式解を使える。[Ruiz](https://epubs.stfc.ac.uk/manifestation/271/raltr-2001034.pdf)・[LAPACK, DGESVX](https://github.com/Reference-LAPACK/lapack/blob/6ec7f2bc4ecf4c4a93496aa2fa519575bc0e39ca/SRC/dgesvx.f)・[Saad & Schultz](https://doi.org/10.1137/0907058)・[Carson & Higham, §8](https://eprints.maths.manchester.ac.uk/2629/1/cahi18.pdf)

## 密 LU に対する追加負荷

n は自由度、k は実際の補正回数、s は平衡化掃引数。通常 LU の分解は約 2n³/3 flop、求解とゲートはそれぞれ約 2n² flop。表は超過時だけ生じる追加の先頭項で、加減・乗除を各1、FMAを2 flopと数えた。絶対値、比較、メモリアクセスと O(n) 項は flop 数の外。いずれも初回通過時の追加分解・補正は0回。

|経路|超過1求解あたりの追加 flop|追加の記憶域|
|---|---:|---|
|補正なし|0|基準となる元行列と LU、ベクトル|
|現行1回 / 案1|約 12kn²（補償残差8、三角求解2、ゲート2）|既存 LU 再利用、O(n) ベクトル。k に依存しない。|
|案2|約 33n²（積と2段 TwoSum で29、求解2、ゲート2）|同上。行ごとの3個の accumulator と O(n) ベクトル。|
|案3|約 2n³/3+(2s+4)n²。各掃引はさらに行・列の最大値を走査する。|元 LU 解放後、スケール行列をそのまま因子化する。行列1枚 8n² バイトの入替え。尺度、右辺、解は O(n)。|
|案4|約 8kn²（元残差、前処理求解、Az、更新後ゲートが各2）|既存 LU と O(n) ベクトル。過去の Krylov 基底を保存しない。|

新方式の作業域見積もりは行列本体を除き、案1・2で 8(n²+3n)+n×sizeof(usize)、案3・4で 8(n²+5n)+n×sizeof(usize) バイト。64 bit・348自由度ではそれぞれ約0.98 MB、0.99 MB。ここには全方式に共通の LU 約0.97 MB が含まれる。共通の LU とピボットを揃えて通常経路の2本分のベクトルを差し引くと、追加の作業域見積もりは案1・2で 8n バイト（348自由度で2.72 KiB）、案3・4で 24n バイト（8.16 KiB）。案3は同時保有行列数を増やさず再分解する。新終端の保存系1求解における追加先頭項は、案1で4.36、案2で4.00、案3で29.06、案4で4.84百万 flop。プロセス全体の実測ピークは本計算表に示す。

### 精度と接線の診断

旧7件では補正が合否を変え、線形求解の丸めが棄却に寄与していた。一方、新終端では案1が3回補正しても、案2が補正右辺の低位成分をさらに保持しても、既存ゲートはともに 1.0882613663018736e−10。元の補正解を80桁の積和で観測した既往値は3.15883e−11、ノルム後退誤差は1.859e−17だった。ゲート側の binary64 行列積の評価丸めも判定に影響する。

同じ新終端の SVD は数値ランク348/348、σmin=0.0166530、次の特異値6.13553、κ₂=3.52862e6。通常 LU の最小 |Uᵢᵢ| は1.97430。旧7件の最後の κ₂=1.156e6 より悪条件で、弱い方向が際立っている。棄却された Newton 接線だけでは、受理平衡の極限荷重や物理分岐を特定できない。各行列については既存観測の SHA-256 を照合して診断を引き継いだ。[旧7系・新終端の固定原票](../2026-11-22-impl-linear-solver/measurements.json)

## 採用判断と NC-01 の判定

**採用なし。** 旧7系と新終端1系をすべて通過した候補は0件。本計算でも案1・2は現行1回補正と同じ到達点、案3・4はそれより手前で止まった。案3の短い wall time には到達範囲の違いが含まれる。計算負荷で選ぶ条件を満たした案はない。既存の1回補正の限定受入は旧7系に対応し、NC-01 の新たな推奨設定を設ける根拠は得られなかった。

全6経路とも撤去工程で真の線形残差が超過し、二分を使い切った。各 Run の全棄却で確定状態の保持を確認した。今回の停止理由に壁時計・メモリ予算超過はない。新終端の弱方向は残っており、ある点で線形ゲートを通過しても、その先の悪条件や物理的不安定を解消したことにはならない。撤去 λ=1 にはどの経路も達しなかった。NC-01b や PC の別実行値を今回の判定には使っていない。

この比較から工程試行上限や物理入力を変更する必要性は示されなかった。別の物理経路や許容値の変更を検討する場合はユーザーの別判断を要する。今回の実行設定の選定について残る判断はない。
