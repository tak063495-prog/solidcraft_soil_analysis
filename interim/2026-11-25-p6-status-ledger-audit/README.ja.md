## 監査の対象と限界

3文書の元表と全日付ラベルの追補を読み、新規監査フォルダーを除く既存interimの `acceptance.json` / `validation.json` / `measurements.json` を再帰的に棚卸しする。今回の検証結果は循環参照を避けて別の `validation.json` / `validation-manifest.json` へ保存する。
各JSONでは `passed` / `accepted` / `complete` / `status` / `conclusion` 等のキーをJSON Pointerと型付き値で保存し、ファイル全体のSHAでも固定する。
全履歴の計算値を再計算したり、ZIP中の数値解を新しく受け入れたりしない。
`passed=true` がソフトウェア検査や限定範囲を意味する場合、`requested_all_* = false` や `P6_complete=false` を併読する。
C-03/C-04/A-01の「限定確認」は限定受入ではない。

監査はファイル存在、現在バイトのSHA-256/blob、指定コミットのバイト、キー値の型と値、引用行、必須対象の網羅、完了宣言、限定範囲、CIのheadと結論を検査する。
新しい非追跡ファイルの作成は読み取るが、既存ファイルを書き換えない。Gitのステージ差分、未ステージの追跡変更、非追跡ファイルも検査する。差分のblob自動再取得を避け、監査中にネットワークを要求しない。
時点/範囲を明示した文書主張を比較し、同一範囲の矛盾はerror、歴史的記述との重なりはwarningとして報告する。
日本語の任意の文章を完全に意味理解する監査ではない。引用分類と範囲は人がレビューする。未登録の変更はSHA不一致で止め、静かに再解釈しない。
終了コード0は証拠照合にerrorがないという意味であり、P6合格や数値受入を意味しない。warning/infoも一覧に残す。errorは1、入力読取エラーは2。
