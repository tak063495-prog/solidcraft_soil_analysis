# 実行時の停止と再実行

- 旧履歴の取得中、同じ起点 SHA の sparse checkout を作り、必要な入力・ソースを先に取得した。C-02 の最初の独立実行は参照モジュール `fem_reference` の取得前に停止した。参照コードを取得して両符号を最初から再実行した。[負の初回ログ](early-face-minus.log)・[正の初回ログ](early-face-plus.log)
- NC 入力の準備時は `refine_tet10` の取得前に停止した。入力生成後、保存済み座標解析の `measurements.json` も未取得だったため、モデル生成で停止した。両方とも全体試行の開始前。元のファイルを取得した後の全体試行は [原票](../nc/global.jsonl) に全件残した。[モデル生成の停止](nc-input-stop.log)
- プローブの初回コンパイルは、診断用の旧相対変位ベクトルが JSON へ直接直列化できず停止した。各ベクトルを成分スライスとして記録するよう修正し、同じ式でビルドした。[初回](build-first.log)・[成功時](build.log)
- 外側 N256 の初回は、再接触の計画ファイルを p15 に探したため途中で停止した。外側の入力・比較先は p15、計画は p17 と同じ p14 の外側計画である。N256 は正しい計画で全工程を再実行した。すでに前段を計算中だった外側 N512・1024 は作業用ディレクトリの参照先を同じ p14 ファイルに向けて継続した。再現スクリプトでは3水準とも直接 p14 を指定する。[初回の停止](outer-256-first.trace)・[初回の時間](outer-256-first.log)
- 別チェックアウトでの事後集計の初回は、過去の Python モジュール `c01_retry_fields` が sparse checkout の対象外で停止した。元コミットのモジュールを展開し、保存した半区間からの再集計で4ファイルがバイト一致した。[再集計のハッシュ](alternate-reread.json)
