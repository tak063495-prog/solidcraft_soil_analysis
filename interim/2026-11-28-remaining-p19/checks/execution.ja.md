# 計算と照合の記録

- ブランチ先端を取得中、同じ SHA の sparse checkout でプローブを先に生成した。最初のビルド準備は p6 の `allocation.rs.inc` が未展開で停止し、次は p8 の `predictor.json` が未展開で停止した。どちらもソルバーの起動前。元コミットの入力を展開してビルドした。[初回](build-input-stop.log)・[2回目](build-predictor-input-stop.log)・[ビルド](build.log)
- NC モデルの構築時、p1 の `increment-4.npz` が未展開で停止した。全体試行の開始前に同じ SHA から復元した。指定通常系列の次親を保存した後、NumPy 真偽値を要約 JSON へ直列化する際に停止した。原票には1,397〜1,399の開始・採否・方向照合が揃っていた。保存済み終端のハッシュを照合して要約を復元し、次の全体試行を1,400から記録した。[入力停止](nc-input-stop.log)・[要約停止](nc-summary-stop.log)・[再開](nc.log)
- C-02 は全3条件を別ディレクトリで再計算し、中心・過去差・公称剰余・認証と葉の支持を含む62ファイルで SHA-256 が一致した。ノルム支持・方向支持に加え、葉別成分支持を全体の成分支持方向に射影して保存することで、自由成分ごとの総ベクトルと葉ごとの寄与を照合できる。[全ファイルの照合](face-reread.json)
- p9 回帰の最初の実行では、sparse checkout に p7 の元経路の場ファイルが揃っておらず、窓の再生成1件が入力読込で停止した。p7 の元の manifest と fields-tail を展開して10件すべてを再実行した。[初回](p9-input-stop.log)・[再検査](p9-tests.log)
- 点19の複数端の根は全実行で観測専用。初回の完走原票では、帯9・10とも点19の根による短縮は0件だった。再実行では帯10の単純割線の選択処理でも点19を明示的に除き、プローブを再ビルドして reverse 終端から照合し直した。最終の生成スクリプトから作ったソースと再実行バイナリのソースが一致した。ソースだけを照合する初回の補助シェルは p15 の生成用ファイル名と衝突して停止したため、補助シェルを別名にして照合した。[ソース照合](probe-source.log)・[原票の再現](reload-reread.json)
