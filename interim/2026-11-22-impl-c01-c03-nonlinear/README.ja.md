- `e8133f0` 系の N256 の分割 ZIP を各 SHA-256 で照合し、試行ごとに最大すべり誤差の GP を抽出した。本体 open の経路誤差棄却148回中143回、reload の151回中145回で、その GP の状態が slip→open になった。両工程とも粗い解と二分割解で終点状態が異なる棄却は0回。open の148回すべて、reload の150回ですべり誤差が元の予算を超えた。独立では open 139棄却すべて、reload 126棄却中125回がすべり超過。PC の N256 本体137/139/143/135回とは別の実行である。
- 既存の全体経路誤差判定は、すべり・散逸の粗密差をそれぞれ基準増分の2乗×既存 scale と比較する。接触ラベルの変化だけでは棄却しない。開閉をまたぐ増分を半分ずつ再試行する間の棄却、滑らかな区間の局所積分誤差、基準格子境界で短く切られた増分からの再成長のすべてが試行を消費する。上記の終点状態一致だけでは Newton 反復中の開閉往復までは特定できない。
- `fa22e14` 系の N512 独立失敗記録を検証し、保存履歴6,882受理点の最後が reload 0.916015625（同工程1,832受理）であること、停止理由が independent stage attempt budget であることを確認した。`2219f90` は切替ラベルの二分、`e8133f0` は経路誤差、`e8aebab` は局所積分と開閉記憶の分解、`026a430` は有限参照を細分した対照。最後の対照では散逸差への局所積分欠損の投影が約98.95〜99.72%であり、すべり差は開閉タイミングに強く依存した。今回も開閉位置と接触内積分を別々に比較する。
- C-03 の PC 報告は12 Tet10 の g32-m0-c0.0001、本体224受理、7/7再開一致、独立 reload 約0.969 で停止。`06695fc` の基準は12 Tet4・open=0.12で、独立も固定32分割で完了していた。独立実装には各固定端点で最大100回の Newton 反復、線探索18候補、必要な内分割の再判定がある。従来は全体の線探索が失敗すると、その端点で経路全体を打ち切る。線形残差超過と材料モデルの例外を分類して扱う。

## 手法の比較と採用理由

|候補|判断と根拠|
|---|---|
|C-01 符号付きギャップの切替位置を予測し、次の増分を基準境界まで等分|採用。誤差超過点の開閉を狙って全体平衡を再求解でき、短い端数を次の格子まで持ち越しにくい。|
|C-01 局所リターンマップの最少4内分割|経路制御と組み合わせる。旧診断が分離した接触内積分欠損を、同じ構成則をより細かく積分して減らす。|
|接触判定へのヒステリシス・活性集合固定・半平滑 Newton|今回は見送り。保存試行で支配的だったのは開閉点のすべり履歴差で、粗密の終点ラベルは一致していた。|
|反復数による荷重増分調整|見送り。平衡反復数だけでは、平衡収束後に検出されるすべり・散逸の経路誤差を観測できない。|
|C-03 独立参照の失敗時二分・確定履歴から再求解|採用。固定端点の非線形反復が停止したときだけ途中平衡を解き、元の指定端点と既存の残差判定を再検査できる。|
|C-03 MC 稜線で既存の主応力順序も満たすまで射影反復を継続|採用。PCと同じ12 Tet10で、相補性の停止条件を先に満たしても主応力順序が不適格となる試行を観測した。同じ増分で両条件を同時に検査できる。|
|拡大ラグランジュ法|今回は見送り。別の接触離散化・乗数更新を導入する根拠が、今回観測した停止理由からは得られなかった。|

PETSc のイベント実装で、符号変化区間を modified Anderson–Björck 法で再分割する処理を確認した。今回使うのは既存の中点試行で区切った区間の割線予測で、PETSc の算法全体を移植していない。PETSc の TSAdaptBasic と SciPy RK は局所誤差から倍率を求め、後者は終端で実刻みを切り詰める。今回、各基準点を通過するために、残区間を予測刻みに最も近い整数個に等分する操作を加えた。[PETSc イベント実装](https://github.com/petsc/petsc/blob/main/src/ts/event/tsevent.c)・[PETSc TSAdaptBasic](https://github.com/petsc/petsc/blob/main/src/ts/adapt/impls/basic/adaptbasic.c)・[SciPy RK](https://github.com/scipy/scipy/blob/main/scipy/integrate/_ivp/rk.py)

OpenSees の LoadControl::newStep は、前増分の反復数と指定反復数の比で荷重増分を調整する。MOOSE の IterationAdaptiveDT::computeFailedDT は失敗した解の刻みを縮小する。MOOSE の RadialReturnStressUpdate は、局所ひずみ増分を内分割して状態を逐次積分する。後者は応力積分の先行例で、摩擦接触精度の参照値には用いていない。[OpenSees](https://github.com/OpenSees/OpenSees/blob/master/SRC/analysis/integrator/LoadControl.cpp)・[MOOSE 刻み制御](https://github.com/idaholab/moose/blob/next/framework/src/timesteppers/IterationAdaptiveDT.C)・[MOOSE 局所積分](https://github.com/idaholab/moose/blob/next/modules/solid_mechanics/src/materials/RadialReturnStressUpdate.C)

## 実装と合格条件

C-01 の入力は `joint_system.global_step_control.path_error` 内の `event_proposal=true` と `minimum_contact_substeps=4`。個別の対照も可能。粗い解・中点・二分割終点の全体平衡を毎回求める。すべり・散逸誤差が予算を超えた接触点だけを対象に、旧・中点・二分割終点で符号が変わる半区間を探し、最も早いギャップゼロを線形予測する。縮小率を1/16〜15/16に収め、区間が見つからなければ二分する。受理後は無次元誤差比から刻みを提案し、次の基準点までを等分する。状態や荷重解の補間を受理する経路はない。各案は旧状態から再求解し、棄却中は履歴を確定しない。分割数の下限は粗・中点・細すべてに同じように適用し、元の5万上限も維持する。両設定を省略すると従来の入力・出力形式と制御を使う。

C-03 の `--nonlinear-cutback` は独立参照の全体 Newton 上限または線探索失敗を受け取り、最後に確定した状態から残区間を二分する。中間点、元の指定端点とも材料の必要内分割を再確認し、力残差1e-10を満たした状態だけを確定する。試行上限2,000/工程、最小増分は入力値。主応力順序だけが不適格なときは、確定状態から同じ目標を再試行し、材料点の射影反復で既存の降伏・相補性・主応力順序のすべてを検査する。射影反復の従来上限20,000でも成立しない場合は増分を二分する。同じ目標の再試行も工程予算に含む。真の線形残差失敗、特異行列、その他の例外は上位へ伝える。固定点の比較ファイルに加えて、途中平衡と棄却理由も保存する。線形解法・構成則・参照値に変更はない。

## クラウドでの比較

12 Tet4 の C-03 対照は、意図的な擬似棄却を使わず、open 係数0.30、N4、材料・接触上限各1e-4を両方式に与えた。旧方式は open 0→0.25 の反復10、相対残差0.00622861で線探索停止。新方式は同じ失敗後に0.125を受理し、0.25への再試行を1回棄却して0.1875、0.25に到達した。目標端点の保存場再組立残差は1.15548e-11、全受理11点の最大3.05611e-11。先行する geostatic・shear の全場と反復記録の SHA-256 は両方式で一致した。別対照の open 係数1.0 は二分後に真の線形残差2.3263e-6で停止した。この失敗も残す。

C-01 独立参照 N512 は、旧方式が保存記録と同じ reload 0.916015625 で2,000試行を消費して停止した（1,832受理・168棄却）。イベント位置・格子整合のみでは目標0.921875まで1,597試行（1,507受理・90棄却）、接触内分割4を併用すると1,062試行（958受理・104棄却、全受理試行の粗・中・細解の力残差最大9.90785e-11未満）。

C-01 独立参照 N1024 の open 44/1024 では、旧方式1,730試行（1,497受理）、イベント位置・格子整合のみ1,270試行（1,179受理）、接触内分割4も併用すると733試行（640受理）。最大力残差は順に9.99983e-11、9.34878e-11、9.92712e-11未満。旧方式と位置予測だけでは残る980個の必須基準点を各1試行で解いても2,000を超える。4内分割併用では当該位置でこの下限が1,713になる。後続の試行数はこの下限からは確定できない。
