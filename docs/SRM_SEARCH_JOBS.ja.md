# 保存・復旧できる乾燥MCのSRM探索

本体656版へ接続した保存型CLIです。同一数値ソースの全Rust347件・Python219件と、実CLIの協調停止・改変拒否・保存障害・新規復旧が合格しました。一般斜面の正確なFs、連続体安定性、設計安全認定、P6全体の完成を意味しません。水・構造・JOINT・材料変更・Davis単調探索などは既存の探索制限を維持します。

```
soil-fem-3d prepare-srm-search-job MESH GROUND CASE SPEC ACCEPTED_INTERVAL NEW_JOB
NEW_JOB/solver/soil-fem-3d.exe run-srm-search-job NEW_JOB [ADVANCE_BUDGET]
NEW_JOB/solver/soil-fem-3d.exe stop-srm-search-job NEW_JOB
NEW_JOB/solver/soil-fem-3d.exe srm-search-job-status NEW_JOB
NEW_JOB/solver/soil-fem-3d.exe verify-srm-search-job NEW_JOB
NEW_JOB/solver/soil-fem-3d.exe prepare-srm-search-recovery NEW_JOB NEW_RECOVERY_JOB
```

Windowsではパスを引用符で囲み、必要に応じて区切り文字を変更します。ファイルパスは新規出力先を指定します。準備ではメッシュ・Ground・全施工Case・探索Specification・現在の実行バイナリをコピーし、ファイルと正規化JSONのハッシュを固定します。途中の施工工程を調べる場合も全Caseと工程数を結び付けます。Specificationは仮想変位場を含め最大256MiB、率候補数などは既存の探索検証で制限します。

各ジョブは一度だけ実行できます。`run.claim`の新規作成で二重実行を拒否します。既存ディレクトリー・既存結果・既存ログへの上書きを拒否します。`status.json`は最終観測の記録であり、PIDが今も動作している証拠ではありません。停止はジョブIDに結び付けた要求を本人が受理増分で確認します。他プロセスをPIDで強制終了する処理は含みません。

停止要求は、同じディレクトリーでflush/syncを終えた一時ファイルをハードリンクで公開します。作成直後の空JSONを計算側が読む競合を避け、既存の別ジョブ用要求を上書きしません。ジョブ先はハードリンクを使えるファイルシステムを使用します。検証先のWindows/NTFSで実行確認します。

初期地圧平衡を完了した保存点で停止要求が届く競合も対象です。復元済みの受理状態がある場合はそのまま保持し、施工途中の状態を地圧平衡の状態へ巻き戻しません。初期化完了直後の停止は数値失敗へ読み替えず、受理済みの保存点として扱います。

探索の元施工も、各率で新規に作る材料履歴も、受理増分で保存します。率を変えるときには前の率の履歴を再利用しません。各保存データを一時ファイルに書き、flush/syncした後で2つの保存スロットを交互に更新し、完成したファイルのSHAと世代番号を原子的に`recovery.json`へ確定します。続けて状態を更新します。途中の書込み失敗では直前の確定ポインターを残します。壊れたポインターを理由なく古いスロットへ読み替えたり、任意のパスを選択したりしません。

`ADVANCE_BUDGET`は1〜10000回の保存単位を実行してから休止する再現用の上限です。`ACCEPTED_INTERVAL`は1〜10000の受理力学増分数です。Newton試行数・計算時間・全体進捗率とは異なります。停止時の終了コードは2、探索計算の完了は0、入力・制御・保存の異常は1です。計算不収束は探索結果の判定不能として保存し、上限へ変換しません。

状態`completed`は探索計算が終わったという意味です。施工ゲートは必ず`requirement`、`search_stop_reason`、独立した上端証拠、適用範囲を確認します。特に`requirement=indeterminate`を合格にしてはいけません。`equilibrium_requirement_met`も指定率で数値的な釣合いを得たという限定した意味で、連続体安定性や設計上の安全を認定しません。

復旧は元ジョブを変更せず、新しいディレクトリーを作ります。元のジョブID・世代・保存ファイルSHA・正規化Snapshot SHAを親情報へ記録します。新しいジョブでも元と同じ実行バイナリが必要です。完了Snapshotも復旧でき、最終レポートだけが壊れた場合は力学計算を繰り返さずに新規ジョブへ再出力できます。初期地圧平衡前の初期Snapshotは準備状態であり、釣合いを得た状態とは表示しません。

検証は、実CLIを使う単軸圧縮の閉形式との比較、全受理履歴の中断なし結果との一致、非線形失敗の判定不能保持、実力学計算中の協調停止、元ジョブの不変性、二重実行拒否、別ジョブのポインター・停止要求・不正パス・壊れたSnapshot・入力変更の拒否、書込み障害後の直前保存点の保持、完成レポートの再出力を対象とします。比較で除くのは計測時間だけです。無低減の完成Runから始める保存探索と、要求率で後続工程を続けるCLIゲートは別コマンドです。SolidCraftの途中工程ゲートUIへの接続、大きい実斜面の探索、入力全般・収束・完成配布などは別の受入項目です。
