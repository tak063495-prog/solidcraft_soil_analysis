# P1体積MCCの表示データ接続

2026-10-26。新方式の表示接続に向け、フレーム抽出、施工監査、外部の完成パケット生成・VTU照合を追加した。**nativeの隔離実装は関連単体試験まで確認し、実アプリの属性入力から求解・3D表示までの通し検証は未完了**である。既存の変位型MCCの表示と受入条件は維持する。

## 保持する量

`soil-fem-view-frame/2` と `soil-fem-view-integration-points/2` を用いる。旧native読込器が新しい意味を暗黙に受け入れないよう、従来の `/1` とは区別する。

|保存場所・量|意味|
|---|---|
|従来の `effective_stress_compression_positive_kpa`|構成則が保持する材料積分点の有効応力。置換しない|
|`primary_mean_effective_stress_compression_positive_kpa`|材料別P1一次圧力を積分点へ評価した平均有効応力|
|`work_conjugate_effective_stress_compression_positive_kpa`|材料応力の偏差成分とP1圧力から作る、釣合いの内部力に使う応力|
|材料/運動学の累積体積ひずみとその差|弱形式で適合する別の場。点ごとの一致を装わない|
|`mixed_primary`|元の節点IDと材料IDの組で識別する圧力・P1体積・凍結適合積分。変位節点へ平均しない|
|材料点値と要素値|生の積分点値と、積分重みで作った要素平均を別に保持する|

同じ位置の異なる材料の圧力は別の行に保存する。除去領域の一次自由度は表示へ含めず、凍結した材料履歴は元の解析結果に残る。`field_semantics` に応力・圧力・体積・識別子の意味、`mixed_equation_audit` に既存の独立再組立の診断を保存する。

フレーム抽出前に `mixed_mcc_io.validate` で全工程の一次状態、体積/圧力/力の残差、掘削時の凍結積分と除去履歴、最終確定状態を確認する。旧形式へ付け替えたmixed状態を拒否する。

`runs/projected-view-fields-20261026-v1/verification.json` に、実CAD由来斜面と二材料柱の計8フレームを記録した。材料応力・釣合い応力・一次圧力・体積・節点/材料IDの全表示値を、既存VTUを別に読み直して照合した。斜面では材料と一次圧力の差が最大約8.895 kPa、二材料境界の圧力差が最大約9.365 kPaあり、それぞれの場を保っている。旧形式への偽装、体積自由度の欠落、凍結積分と力残差の改変を両モデルで拒否した。既存の表示契約7試験も合格した。

これは既に計算された結果の表示データ試験である。新しい独立物理解や空間収束の合格ではなく、SolidCraft上の新形式の入力・実ジョブ・GPU表示もまだ検証していない。

## 施工監査と完成パケット

`verify_stage_package.py` は投影MCC結果を `verify_projected_stage_package.py` へ分岐する。地形と重量・面荷重からの外力再組立、K0/pc/eまたは一般地圧平衡の元履歴、工程の圧力/境界係数、有効領域、モニター、材料降伏、支持反力・力/モーメント、掘削時の保持荷重を検査する。P1体積・圧力・適合積分と除去材料履歴の検査も維持する。監査済み記録を上書きしない。

掘削では、単に旧一次圧力の行を残すだけでは正しくない。材料の偏差応力と履歴を保持し、残存領域に対して平均材料圧力を整合P1質量行列で再投影して、保持荷重を組み立てる。独立監査は行列を陽に全体密行列へ展開せず、対角前処理CGと元作用素の真残差でこの圧力投影を解く。未変更の領域では保存済み一次場とその弱残差を検査し、別解で置換しない。

`runs/projected-stage-audit-20261026-v5/verification.json` には実斜面・二材料の8フレームと、入力工程・領域・保持荷重・撤去体積・モニター・重量・圧力の改変拒否14条件を記録する。先行v1は残存領域での再投影を省略した監査、v2は一つの負例が元の圧力と同じ値だった試験、v3は初期の一次場を別解へ置換した監査が失敗した記録である。原因を修正し、判定値を緩めていない。

実際の開発ソルバーで、面圧載除荷→表示RESET→境界載除荷→掘削の7フレーム/29受理増分、および重なる指定集合を一度だけ数える2段階局所掘削の5フレーム/24受理増分も解き、監査した。記録は `runs/projected-pressure-display-audit-20261026-v1/verification.json` と `runs/projected-multiple-cut-audit-20261026-v4/verification.json`。局所掘削試験の先行v1〜v3では、ツール対応の欠落、既存表面だけに載荷する指定の欠落、地中から掘り始める不適切な領域をRustが求解前に拒否した。入力を修正し、それらの検査は保持した。

外部パケットは `soil-fem-solidcraft-view/2` として生成する。一次場をVTUと照合し、一次圧力を書き換えてファイルSHAだけを付け直したパケットも拒否する。`runs/projected-view-packet-20261026-v2/verification.json` の計11フレームは**実数値結果を合成CAD受渡し情報で包んだ転送試験**であり、実SolidCraft出力・STEP形状・メッシュ対応や画面の証拠ではない。v1の大きな積分点初期値が既存の入力サイズ制限を超えた拒否も保持し、サイズ上限は引き上げていない。既存表示7試験とワーカー12試験も合格した。

外部出力時の全履歴検査を、フレームごとの反復から出力全体で1回へまとめた。出力前の施工監査で全工程・凍結履歴を検査し、各フレームの抽出ではそのフレームの独立再組立を維持する。4/7フレームの各出力で全履歴検査がちょうど1回になり、従来の全フレーム・全GP・形状JSONのバイト一致と、単独 `scene_frame` 呼出しの全履歴検査、改変拒否、既存表示7試験を確認した。記録は `runs/projected-view-export-scaling-20261026-v1/scaling-verification.json`。工程数に対する全履歴再検査の二乗増加を除いたもので、大規模モデルの実測時間/RSSやP6性能の受入ではない。

次は新ファミリーの属性入力、native読込/量選択/生値表示へ接続し、実アプリの出力から求解・監査・3D表示まで検証する。P0〜P6全体の未完項目は引き続き [受入一覧](P6_STATUS.ja.md) で管理する。

## native側の隔離実装

`external/solidcraft-projected-ui` に、同じ上流コミットと従来47ファイルを固定して別のGit作業ツリーを作った。従来の `external/solidcraft-soil-fem` の総合CI対象から分離している。新方式の選択、乾燥MCC/対応施工の入力検査、Tet10の開始前検査、パケットv2読込、材料別一次自由度とTet10変位からの表示値再構成、材料/釣合い応力の量選択、P1圧力/体積の線形補間、一次自由度・生GP値の照会を追加した。エンジンの関連試験は29件合格、既存の外部実解析データを必要とする1件は未実行である。解析値を手で指定した転送例で、圧力10〜40 kPaのP1変化が要素平均へ潰れないこと、Tet10ひずみ再構成と改変拒否を確認した。UIにも節点と材料を組にした照会欄を追加した。**アプリ本体はビルド中であり、実モデルの新形式によるnative接続・実画面の合格根拠にはまだしない。** 固定ソースと試験範囲は `runs/native-projected-ui-20261026-v2/engine-verification.json` に記録した。

従来版の総合CI v3は全試験バイナリのビルドを終えたが、Windowsパスの診断文字列、CRLFのアイコン一覧、追加した解析ウィンドウ幅の3検査が失敗した。多数の試験が同時に動いている実行を所有セッションから中断し、対象CIイメージが残っていないことを別に確認した。FEMの2ジョブは別ハンドルで継続している。

診断パスを `/` に統一し、アイコン一覧はCRLFのみ正規化して全項目・順序を維持し、解析パネルは既に指定した2.5カード幅の契約を幅試験へ追加した。新規のバイナリ実行キューは既定最大4ジョブ、明示 `SOLIDCRAFT_TEST_JOBS=1..64` とし、全エントリーを一度ずつ実行する2試験を追加した。xtaskの33試験は合格。総合CI v4は51ファイルの固定ソースで再実行中であり、全体の合格ではない。ログ・固定ソース・再開情報は `runs/native-projected-ui-20261026-v1/` と `runs/native-cooperative-ci-20261026-v4.log` に残す。

その後v4は警告禁止clippyで試験モジュールの配置を検出して終了した。試験内容を変えず `cfg(test)` モジュールをファイル末尾へ移し、v5で全ターゲットのclippyを通過した。現在は全試験のビルドを継続している。v5は同じ主作業ツリーの既にビルド済み `xtask.exe ci` から実行し、アプリのdebugビルドとCargo起動部分のロックを競合させていない。実行側の非試験コードと試験内容のトークンがv4と同一であること、全てのCI工程が維持されていることを `runs/native-projected-ui-20261026-v2/main-ci-v5-source.json` に記録した。ログは `runs/native-cooperative-ci-20261026-v5.log`。全体品質・P6全体は引き続き未完了である。
