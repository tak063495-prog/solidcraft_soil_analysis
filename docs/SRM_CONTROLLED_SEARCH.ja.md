# SRM探索の受理増分ごとの保存

本体656版へ接続したRust APIです。同じ数値ソースの全Rust347件・Python219件と、MCCの塑性/局所掘削中の停止・再開が合格しました。所有ジョブ・原子的ファイル保存・復旧用ディレクトリーは[保存型CLI](SRM_SEARCH_JOBS.ja.md)から使用できます。SolidCraftの途中工程ゲート操作画面は未接続です。

`srm_search_control::Snapshot::start`に元のメッシュ・Ground・全施工Case・探索Specificationを渡します。`advance`は正の受理増分数を上限として進め、新しいSnapshotを返します。元の施工の初期地圧平衡も保存対象です。各低減率では元の入力から新規に履歴を作り、同じ率の中断状態だけを既存の力学Checkpointで再開します。前の率の変位・塑性履歴・荷重を次の率へ引き継ぎません。

Snapshotは元の全入力・探索条件・実行バイナリ・全保存内容のSHA256を保持します。途中工程の探索でも全Caseを結び付けます。JSONの読み書きを挟んで再開し、変更した材料・形状・施工・要求率・仮想変位場・バイナリ・履歴は拒否します。チェックサムは改変検出用であり、第三者の正しさを保証する署名ではありません。

受理済み状態だけを力学Checkpointとして保存します。切戻し中の試行を受理状態へ置き換えません。計算上の不収束は判定不能とし、独立した平均応力または全積分点の仮想仕事による排除だけを探索上端に使います。要求率の評価と未低減の元施工履歴を保持します。結果の「釣合いを得た率」は連続体の安定下界・設計安全認定ではありません。

外部Observerの停止要求は受理増分で確認します。制御・保存・入力エラーは終端エラーとして返します。呼出側は成功したSnapshotだけを新しい保存先へ原子的に確定し、失敗時は直前の保存点を保持する必要があります。旧保存点の上書きや、失敗後の未保存メモリー状態の再開を要求しません。完成したファイルジョブの実装は別工程です。

検証対象は単軸圧縮の閉形式、安全率探索全体と履歴の中断なし結果との一致、非零自重を持つ初期地圧平衡、支持条件が分布した摩擦性材料の仮想仕事上端、切戻し後の再開、実際の非線形失敗、入力/履歴改変拒否、Observer異常時の旧保存点保持です。計測時間だけを除いて比較します。無低減epoch起点の保存探索と、CLI上の途中工程ゲートは別経路です。一般斜面の正確なFs、2D変位差の5％基準、一般3D収束、水・構造との探索、施工ゲートのNative画面、P6全体は未完です。
