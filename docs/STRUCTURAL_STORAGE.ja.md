# 構造系の明示的容量・行列記憶域制御

限定した力学受入を経て本体へ取り込みました。従来入力の構造節点上限500、部材＋板2000、縮約内部自由度3000と、機構・悪条件・物理残差の検査を保持します。

beam_systemまたはコンパクトなplate_surfacesへ、明示的にstorage_budgetを指定した場合だけ拡張します。省略した従来入力は既存の組立経路を使い、追加フィールドを結果へ出力しません。

```json
{
  "storage_budget": {
    "maximum_nodes": 750,
    "maximum_compilation_mib": 1024,
    "maximum_cached_mib": 512
  }
}
```

節点上限は最大1000、1回の構造系コンパイルで見積もる行列記憶域は最大2048 MiB、保持するコンパイル済み行列キャッシュは最大1024 MiBです。これは構造系の密行列・作業行列の保守的な事前見積もりとキャッシュ行列の上限であり、解析全体・Python・GPU・OSの総メモリー上限ではありません。既存キャッシュや呼出側が保持する評価値は、1回の行列生成の見積もりとは別です。

拘束基底と付着写像の非零成分を使ってKqq/Kqt/Kttを組み立て、元の静的縮約と同じ全非局所結合を保持します。大きな密行列を確保する前に自由度と記憶域を検査し、符号や対称性を都合よく変更する安定化は加えません。Choleskyの機構判定、1e-12の対角基準、1e-9の物理内部残差基準を変更していません。

キャッシュが指定上限を超える場合は破棄して同じ行列を再計算します。max_cached=0も許可し、有限の履歴を変えずにキャッシュを保持しない比較ができます。保存再開時の温まったキャッシュに依存する値は物理履歴へ混ぜません。

受入には、独立な密行列積との比較、容量の不正値・オーバーフロー・確保前拒否、キャッシュ破棄前後の一致、梁の理論解、MC/MCC/混合形式と板の載除荷・設置撤去・切戻し・再開、全回帰、既存274要素の全履歴不変性、同じモデルの独立100/200分割照合、Nativeで宣言した662節点・1264板の全工程とメモリー観測が必要です。大きいモデルのGPU表示や空間収束は別の受入条件です。


## 検証記録と現在の限界

分離した609ソース版のRust269件・Python162件、clippyが合格しました。従来設定の274要素モデルは旧版と全8群の物理履歴が完全一致し、容量を明示した同じモデルの1/16・1/32も独立RK4 100/200分割の原基準を通過しました。

実SolidCraftの11ボディ・2材料・662構造節点・1264板・2807 Tet10では、全5工程と75789初期GPの種状態、7506撤去GPの履歴凍結、3棄却時の復元、独立の力と面積積分を照合しました。掘削6.25％で協調保存し、新規ジョブへ再開した結果も、連続計算と全8群の物理履歴が完全一致しました。比較から除いた値は経過時間だけです。

このモデルの底面8 m²の平均掘削増分隆起は6.825508 mm、累積変位は+0.727111 mmです。周辺32 m²の地表は掘削増分−0.028887 mm、累積−16.770905 mmです。現地同定値ではありません。壁と地盤の分割が従来の各モデルと異なり、この値の近さを空間収束と扱いません。

同時実行下で連続解析の壁時計11585.354秒・CPU11558.875秒、OSピークworking set1283072000 bytes・commit1459154944 bytesを観測しました。16論理CPUのPCで、観測は起動後から、ピークはOSの生涯カウンターです。解析全体のメモリーは指定した構造行列予算を超え得ます。分離したスループット測定や1万・10万要素の受入ではありません。

大きい結果のNative表示は未受入です。元の535711781 bytesの結果JSONが従来の256 MiB読込上限で拒否されました。空白だけを除く変換も同じ上限を超えたため、元の履歴と未達記録を保持し、原本をハッシュ照合した上で必要な工程を読み込む経路を継続して実装します。上限を外したり、材料点を省いた結果を受入済みとして扱ったりはしていません。既存945要素のNative受入と区別します。
